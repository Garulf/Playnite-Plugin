# Playnite Plugin LiteDB Rewrite - Design

Date: 2026-08-24
Status: Approved pending user review

## Goal

Rewrite the Playnite Flow Launcher plugin (v2.0.0, flox-lib, requires the
FlowLauncherExporter Playnite extension) as a dependency-free v3.0.0 in the
Steam-Search style: `pyflowlauncher` on Flow's `python_v2` runtime, reading
Playnite's `games.db` directly with `litedb-py`. No Playnite-side extension
required.

## Identity

Unchanged so the plugin manager updates users in place:

- ID: `625A2812D5364D708582FDD9ACCD8C93`
- Name: `Playnite`
- ActionKeyword: `pn`
- Version: `3.0.0`, `Language: python_v2`

## Repository layout (mirrors Steam-Search)

```
data/
  plugin.json            # manifest (identity above)
  SettingsTemplate.yaml  # settings UI
  icon.png               # reused from v2
src/
  run.py                 # generic shim, verbatim copy from Steam-Search
  plugin/
    __main__.py          # pyflowlauncher Plugin wiring, query handler
    playnite.py          # library location, DB copy/cache, Game model, URIs
    results.py           # Result/context-menu/error-result builders (testable)
tests/                   # pytest, run via tox
docs/README.md.j2        # readwright template
readme.yaml              # readwright config
requirements.txt         # pyflowlauncher, litedb-py
```

## Library reading (`playnite.py`)

- Default data dir `%APPDATA%\Playnite`; `playnite_path` setting overrides
  (portable installs). Database at `<data dir>\library\games.db`.
- Playnite locks the file while running, and litedb-py is read-only, so the
  plugin copies `games.db` to a temp/cache location and opens the copy with
  `LiteDatabase`. The copy is cached keyed on the source file's mtime and
  size; unchanged source means no re-copy.
- Read the `Game` collection from `games.db` (verified against a real
  library: it contains only `Game`). Source names live in a sibling
  `library\sources.db`; resolve `SourceId` GUIDs against it when present,
  and degrade to no source label when it is missing or unreadable.
- `Game` model fields: `Id`, `Name`, `IsInstalled`, `InstallDirectory`,
  `Icon`, `CoverImage`, `Hidden`, `Playtime`, `LastActivity`, `Links`,
  source name.
- Media paths resolve against `<data dir>\library\files\<relative path>`
  (`Icon` for the result icon, `CoverImage` for the F1 preview).

## Query behavior (`__main__.py`)

- All games are searchable, installed or not. Hidden games are excluded
  unless the `show_hidden` setting is on.
- Fuzzy matching via `plugin.launcher.api.fuzzy_search`, identical to
  Steam-Search: empty query lists everything, non-empty query filters on
  the score cutoff and uses the score for ranking.
- Result: title = game name; subtitle = source, install state, and
  playtime/last-played when present; icon = resolved `Icon`; F1 preview =
  resolved `CoverImage`.
- Selecting a result: installed games open
  `playnite://playnite/start/{Id}`; uninstalled games open
  `playnite://playnite/showgame/{Id}`.

## Context menu

Entries appear conditionally:

- Launch / Install (`start` URI; label follows `IsInstalled`)
- Show in Playnite (`showgame` URI)
- Open install folder (Explorer on `InstallDirectory`; only when installed
  and the directory exists)
- One entry per `Links` item (Store Page, wiki, etc.), opening the URL
- Copy game Id to clipboard

Playnite's URI handler only supports `start`, `showgame`, and `search`, so
uninstall and other actions are out of scope by decision: the plugin stays
dependency-free rather than shipping a companion Playnite extension.

## Settings (`SettingsTemplate.yaml`)

- `playnite_path` - Playnite data directory override (default
  `%APPDATA%\Playnite`)
- `show_hidden` - include hidden games (default off)

## Error handling

Failures surface as a single informative result, never a crash:

- Playnite dir or `games.db` missing: points at the settings dialog.
- `UnsupportedVersion` / `EncryptedDatabase` from litedb-py: message
  explaining the database cannot be read.

## Testing

- pytest via tox against a small committed LiteDB v4 fixture database
  (generated with litedb-py's fixture generator) covering: DB copy/cache
  behavior, `Game` parsing and source resolution, hidden filtering, media
  path resolution, URI building, and subtitle formatting.
- The Flow-runtime pieces (fuzzy_search, JSON-RPC) stay thin and untested
  locally; they need Flow Launcher on Windows.

## Tooling

- uv for dependency management; tox + pytest.
- pre-commit: gitleaks, hygiene hooks on commit; pytest on pre-push.
- Conventional Commits; release-please for versioning/changelog/releases.
- Release workflow modeled on Steam-Search's `release.yml`: assemble the
  plugin zip (manifest + `src` + dependencies vendored into
  `plugin/site-packages`) and attach it to the GitHub release.
- README generated by readwright from `readme.yaml` + `docs/README.md.j2`,
  following the Steam-Search configuration.
- README screenshots generated with flow-render from a curated config
  (games and subtitles derived from the real library, icons taken from
  Playnite's own `library\files` media), plus the plugin-manager install
  view. No live Flow Launcher needed.
